# ЦЕЛЬ И ОГРАНИЧЕНИЯ

Плеер индексирует "AllMusic" по WebDAV, показывает медиатеку по трекам,
альбомам и исполнителям, воспроизводит музыку через временный кэш.
Плейлисты и избранное НЕ нужны: не реализуй и не закладывай под них UI.

- Windows, Android (minSdk 24, уточнить в ADR) и Linux x86_64, единая
  кодовая база.
- Android БЕЗ GMS: никаких Firebase, Play Services, Cast, ML Kit, Play Core,
  Google Sign-In и транзитивных зависимостей на них. Распространение — APK.
  Тест на AOSP-образе эмулятора (без Google APIs/Play).
- Linux: целевая среда — GNOME 51, сессия Wayland. X11-сессия не
  поддерживается (GNOME 50 её убрал). ARM Linux и другие окружения (KDE и
  др.) вне задачи, но приложение не должно намеренно их ломать. Целевые
  дистрибутивы (CachyOS/Arch и/или ALT Linux) и минимальная версия GNOME —
  уточни в docs/OPEN_QUESTIONS.md и зафиксируй в ADR; версию GNOME на ALT
  Linux не предполагай, а выясни.
- Без телеметрии и аналитики. Только HTTPS к серверу WebDAV.
- Источник — только WebDAV Cloud.Mail.ru, корень "AllMusic". Эндпоинт
  (ожидается https://webdav.cloud.mail.ru — проверить) и аутентификация
  (ожидается Basic с «паролем для внешних приложений» — проверить) уточни по
  актуальной документации и опиши в README.
- Монтирование диска средствами ОС (служба WebClient на Windows, GVfs/davfs
  на Linux) как основной путь НЕ использовать (лимиты, нестабильность) —
  зафиксируй в ADR.

# ТЕХНОЛОГИИ ПО МОДУЛЯМ

Общее решение (ADR-001): Flutter (stable, Dart 3.x), Material 3, единая
кодовая база. Альтернативы для сравнения в ADR: Kotlin Multiplatform/Compose
(+ Media3 и desktop-движок), Tauri/Rust. Критерии: GMS-free, один код на три
платформы, качество аудиостека на Windows и Linux, скорость vibe-разработки.

## A. Окружение и инструменты
- Flutter SDK через FVM (.fvmrc, версия закреплена и в CI). Dart: sealed
  classes, records, pattern matching.
- Windows-сборка: Visual Studio 2022 с нагрузкой "Desktop development with
  C++", включённый Developer Mode (симлинки плагинов).
- Android: Android SDK, JDK 17, эмулятор с AOSP-образом без Google APIs.
- Linux-сборка: clang, cmake, ninja, pkg-config, заголовочные файлы GTK,
  libmpv, libsecret, SQLite; для упаковки — flatpak и flatpak-builder.
  Точный список пакетов для Arch и для ALT Linux проверь при сборке и
  запиши в README.
- Кодогенерация: build_runner (команда в AGENTS.md; сгенерированные файлы не
  править руками; решить в ADR, коммитить ли *.g.dart/*.freezed.dart).
- Линтер: flutter_lints + доп. правила (always_declare_return_types,
  prefer_final_locals, unawaited_futures, avoid_print, require_trailing_commas).
  riverpod_lint/custom_lint — опционально, только если стабильно работают.

## B. Ядро приложения
- Состояние и DI: flutter_riverpod + riverpod_annotation + riverpod_generator.
- Модели: freezed + freezed_annotation (иммутабельные сущности и union-типы);
  ошибки домена — sealed-классы (без пакетов Result/Either).
- Навигация: go_router; ShellRoute/StatefulShellRoute для вкладок и
  постоянного мини-плеера (см. раздел K).
- Утилиты: collection, meta, path, path_provider, crypto (хэши ключей кэша),
  pool (ограничение параллелизма). Пути всегда через пакет path, без
  ручных разделителей.
- Логирование: пакет logging + собственный файловый sink с ротацией и
  обязательной маскировкой Authorization/паролей.
- Локализация: flutter_localizations + intl, ARB, ru по умолчанию.

## C. Сеть и WebDAV-клиент
- HTTP: dio (CancelToken, ResponseType.stream, Range-запросы,
  interceptors); IOHttpClientAdapter с ограничением maxConnectionsPerHost,
  keep-alive, таймаутами connect/receive.
- WebDAV-клиент — СВОЙ тонкий слой (lib/data/webdav) поверх dio: PROPFIND
  Depth:1, HEAD, GET с Range, условные запросы по ETag, разбор multistatus.
  Обоснование: полный контроль над Range/ETag/отменой и поведением Mail.ru;
  готовые WebDAV-пакеты малоупотребимы и слабо поддерживаются. ADR.
- Разбор XML: пакет xml; большие ответы разбирать в isolate (Isolate.run).
- Auth: собственный interceptor (Basic), пароль берётся из SecureStore.
- Повторы: собственный interceptor — экспоненциальная задержка с джиттером,
  только для идемпотентных методов (PROPFIND, GET, HEAD), уважение Retry-After
  и кодов 429/503.
- Параллелизм: pool.Pool с лимитом соединений (значение — по результатам
  spike о rate limits Mail.ru).
- Состояние сети: connectivity_plus. На Linux он зависит от NetworkManager
  через D-Bus: проверить поведение без NetworkManager; запасной путь —
  реагировать на ошибки запросов и по таймеру повторять проверку.
- ЗАПРЕЩЕНО: cronet_http и любые клиенты, завязанные на Google Play Services.
- Запасной вариант клиента: package:http + собственный Range-слой.

## D. Локальная БД и индекс
- drift (+ drift_dev) поверх SQLite; NativeDatabase.createInBackground
  (БД в фоновом isolate), WAL, внешние ключи.
- Нативный SQLite: sqlite3 + sqlite3_flutter_libs (или актуальный механизм из
  документации drift) — проверить сборку на Windows, Android и Linux. На
  Linux убедиться, что в используемой библиотеке доступен FTS5; если нет —
  использовать встроенную сборку SQLite, решение в ADR.
- Поиск: FTS5-виртуальная таблица через drift; нормализация запроса в Dart
  (регистр, ё→е).
- Миграции: drift schema versioning + тесты миграций (drift_dev schema).
- Таблицы (минимум): remote_files(path, etag, size, mtime, status), artists,
  albums, tracks, scan_state (чекпоинты), cover_cache_index, audio_cache_index.
- Списки на 50 000+ треков: постраничная выборка (keyset/окна), не грузить всё
  в память; ListView.builder/SliverList с фиксированным itemExtent.
- Запасной вариант: sqflite_common_ffi + sqflite (Android) — только если
  drift не соберётся.

## E. Индексатор и синхронизация
- Фоновая работа: dart:isolate (долгоживущий isolate-воркер со своим
  соединением к БД, обмен через SendPort/ReceivePort; пачки — Isolate.run).
- Обход дерева: PROPFIND Depth:1 рекурсивно с ограниченным параллелизмом
  (Depth:infinity обычно запрещён — проверить в M0).
- Инкрементальность: сравнение ETag/size/mtime; добавление новых, удаление
  исчезнувших, перечитывание тегов только у изменённых; чекпоинты в
  scan_state — возобновление после прерывания; отмена и прогресс в UI.
- Синхронизация работает пока приложение открыто (WorkManager и прочие
  фоновые задачи вне объёма). Запись в ADR.

## F. Теги и метаданные
- Основной парсер: audio_metadata_reader (чистый Dart; MP3/ID3, FLAC, MP4/M4A,
  OGG Vorbis/Opus, WAV) — проверить в M0 на реальных файлах коллекции.
- Чтение через Range: качать начало файла (по умолчанию 256 КБ, расширять до
  разумного лимита при большом ID3v2/APIC) во временный файл и парсить;
  для MP4 при moov в конце — запрашивать хвост. Целиком файлы ради тегов не
  качать.
- Кодировки: частая проблема русских коллекций — cp1251 в ID3v1/ID3v2
  (кодировка помечена как Latin-1, а текст на деле Windows-1251). Использовать
  enough_convert (чистый Dart) + эвристику определения; правило — в ADR,
  покрыть тестами.
- Запасной вариант: собственный минимальный парсер ID3v2/FLAC/MP4-атомов
  поверх интерфейса RangeReader; затем — разбор структуры папок
  AllMusic/Исполнитель/Альбом/файл и имени файла.
- Правила группировки (album artist vs artist, сборники, мультидиск) — ADR.

## G. Обложки
- Обработка: пакет image (чистый Dart) в isolate: decode → масштаб так, чтобы
  большая сторона ≤ 1200 px с сохранением пропорций, без апскейла → JPEG,
  quality 85. Учитывать EXIF-ориентацию; пропускать входные картинки
  аномального размера (лимит — ADR).
- Источники: встроенная обложка из тега, затем cover/folder/front.(jpg|png) в
  папке альбома (через WebDAV).
- Кэш: собственный CoverCache — файлы в каталоге кэша приложения, ключ =
  sha1/sha256(источник + etag + size), индекс в drift, LRU-вытеснение по
  суммарному размеру (лимит по умолчанию обосновать, настраивается).
- Отображение: Image.file + ResizeImage/cacheWidth по размеру виджета (не
  держать полноразмерные декодированные картинки в списках); плейсхолдер.
- Запасной вариант, если image окажется медленным: flutter_image_compress
  (нативный) только там, где он поддерживается на ВСЕХ трёх платформах,
  иначе — разные реализации за интерфейсом; решает ADR по замерам на M3.
- ЗАПРЕЩЕНО: cached_network_image (кэш по нашей схеме, а не по URL).

## H. Воспроизведение (аудиодвижок и очередь)
- Движок: just_audio. На Android — нативный ExoPlayer (Media3), на Windows и
  Linux — just_audio_media_kit (libmpv через media_kit; для Windows
  предпочесть audio-only сборки media_kit_libs_windows_audio; для Linux —
  соответствующий libs-пакет, который проверить в M0). ADR: сравнить с
  вариантом «media_kit на всех платформах» (media_kit +
  media_kit_libs_android_audio + media_kit_libs_windows_audio +
  media_kit_libs_linux). Критерии: seek по Range, передача
  Authorization-заголовков, gapless, стабильность, форматы. Проверить
  лицензионные последствия бинарников libmpv (LGPL/GPL) для распространения
  и записать в ADR.
- Аудиофокус, наушники, прерывания: audio_session.
- Логика очереди — СВОЯ доменная сущность QueueController (независима от
  движка): порядок, исходный список (треки/альбом/исполнитель), shuffle
  (Fisher–Yates, текущий трек остаётся первым, при выключении порядок
  восстанавливается), repeat (выкл/весь список/один трек), поведение на
  границах и при ручных next/prev в режиме «один трек».
- Движку отдаётся скользящее окно из двух элементов (текущий + следующий) —
  это даёт gapless и совпадает с политикой кэша; использовать актуальный API
  плейлиста just_audio (setAudioSources/ConcatenatingAudioSource — проверить,
  какой не deprecated).
- Интерфейс PlayerEngine в domain; реализация JustAudioEngine в data;
  реализация подменяема на MediaKitEngine.
- Форматы: mp3, flac, m4a/aac, ogg/opus, wav. WMA не гарантируется
  (ExoPlayer его не поддерживает) — зафиксировать.
- Сохранение состояния (очередь, позиция, shuffle/repeat): shared_preferences
  для режимов, drift для очереди.

## I. Временный кэш аудио
- Политика: хранить ТОЛЬКО текущий и следующий трек; при смене трека
  предыдущий удаляется; при старте — очистка осиротевших файлов; жёсткий
  потолок размера.
- Хранилище: getTemporaryDirectory()/audio_cache; имя файла =
  hash(path+etag); запись в .part с атомарным переименованием по завершении;
  индекс в drift.
- Стратегия (решение — ADR по итогам spike в M0), два кандидата:
  (1) LockCachingAudioSource из just_audio (локальный прокси, один поток
      скачивания, одновременно кэш и воспроизведение);
  (2) собственный загрузчик на dio: Range-докачка в .part, воспроизведение
      потоком с заголовками до готовности файла, затем AudioSource.file.
  Критерии: время до первого звука (цель 2–3 с), seek до полной загрузки,
  стабильность на Windows и Linux (media_kit) и Android, обрывы сети.
- Предзагрузка следующего трека, отмена загрузки при смене трека (CancelToken),
  докачка с экспоненциальной задержкой.

## J. Системная интеграция (реализации за интерфейсами в lib/platform)
- Интерфейсы: MediaSessionBridge, WindowController, SecureStore.
- Android: audio_service (AudioHandler, MediaSession, foreground service типа
  mediaPlayback, уведомление с управлением, кнопки гарнитуры и Bluetooth);
  permission_handler для POST_NOTIFICATIONS (Android 13+). Проверить в M7
  работу сети при погашенном экране (wake/wifi lock) и поведение при
  энергосбережении.
- Windows: smtc_windows (System Media Transport Controls и мультимедийные
  клавиши, метаданные в оверлее громкости); window_manager (размер/позиция
  окна, минимальный размер, сохранение между запусками); горячие клавиши
  внутри приложения — Flutter Shortcuts/Actions/CallbackShortcuts.
- Linux (GNOME 51, Wayland): MPRIS через D-Bus — основной путь. Реализация:
  пакет dbus (чистый Dart) либо готовый MPRIS-плагин для audio_service;
  выбрать в M0 по проверке на живой оболочке. Требования: интерфейсы
  org.mpris.MediaPlayer2 и .Player, метаданные (title, artist, album, length,
  artUrl), управление play/pause/next/prev/seek, корректный DesktopEntry
  (должен совпадать с именем .desktop-файла и app id). Медиаклавиши НЕ
  перехватывать: их обрабатывает GNOME и направляет в MPRIS. Обложка
  (artUrl) должна быть по пути, который видит оболочка (хост, не песочница
  Flatpak) — проверить в M0, запасной вариант фиксируется ADR.
  window_manager на Linux использовать только для размера, минимального
  размера и состояния «развёрнуто»: на Wayland приложение не может задавать
  позицию окна, поэтому позицию не сохранять и не восстанавливать. Системного
  трея в GNOME нет — значок в трее НЕ делать. Поведение при закрытии окна
  (остановить воспроизведение или продолжить в фоне) — решение в ADR.
- Запасные варианты: SMTC — собственный плагин на C++/WinRT; MPRIS —
  собственная реализация на dbus поверх интерфейса. Только через ADR.

- Мини-плеер: оболочка go_router (ShellRoute) — постоянная область на ВСЕХ

  прогресса; по тапу — экран «Сейчас играет».
- «Сейчас играет»: полноэкранный маршрут — обложка, название/исполнитель/
  альбом, Slider позиции со временем, play/pause, prev/next, shuffle, repeat.
- Медиатека: вкладки Треки/Альбомы/Исполнители; Исполнитель → Альбомы →
  Треки, Альбом → Треки; поиск.
- Настройки: подключение (логин, пароль приложения, проверка соединения),
  пересинхронизация, лимиты и очистка кэшей, тема, «О программе» (версия,
  showLicensePage).
- Пустые состояния и ошибки на русском: нет сети, неверные учётные данные,
  AllMusic не найдена, трек недоступен.
- Сторонних UI-компонентов по минимуму: только встроенные виджеты Flutter.
  Имитировать libadwaita НЕ нужно.

## L. Безопасность и настройки
- flutter_secure_storage для учётных данных за интерфейсом SecureStore:
  Android Keystore, хранилище Windows, на Linux — libsecret (Secret
  Service: gnome-keyring). В Flatpak доступ к секретам идёт через портал;
  проверить в M0, что пароль сохраняется между запусками внутри песочницы.
  Если Secret Service недоступен — понятная ошибка на русском и запасной
  вариант (зашифрованный файл с ключом из хранилища ОС либо ввод пароля при
  запуске), только через ADR.
- shared_preferences для обычных настроек; package_info_plus для версии.

## M. Тестирование и CI
- Unit/виджет: flutter_test + mocktail; БД в тестах — drift in-memory
  (NativeDatabase.memory); интеграционные: integration_test.
- Сервер для интеграционных тестов: WsgiDAV (Python, pip) — скрипты в /tools
  (запуск локально и в CI); реальный аккаунт в автотестах не используется.
- Тестовые аудиофайлы генерируются скриптом (ffmpeg) с разными тегами,
  кодировками (в т.ч. cp1251), обложками; в репозиторий кладутся только
  маленькие фикстуры PROPFIND (анонимизированные).
- Покрытие: flutter test --coverage; логика очереди/кэшей/группировки ≥ 80%.
- CI: GitHub Actions — subosito/flutter-action (версия из .fvmrc),
  actions/setup-java (Temurin 17). Задания: analyze + test + check_layers +
  check_no_gms на ubuntu-latest; сборка Android на ubuntu-latest; сборка
  Windows на windows-latest; сборка Linux в контейнере с зависимостями
  (GTK, libmpv, libsecret) и проверкой запуска без графики там, где это
  возможно; артефакты — APK, Windows-сборка, Linux-бандл; Dependabot для pub
  и Actions.
- Проверка отсутствия GMS: tools/check_no_gms (.sh и .ps1) — поиск
  com.google.android.gms/firebase в дереве зависимостей Gradle и в
  AndroidManifest/dex (apkanalyzer/aapt); запускается в CI.
- Ручное тестирование (автоматикой не покрывается): звук, MPRIS-панель,
  медиаклавиши, масштабирование, Flatpak-песочница, поведение при
  закрытии окна. Чек-листы по платформам — docs/TESTING_MANUAL.md;
  для GNOME 51 — на образе GNOME OS либо на дистрибутиве с GNOME 51 в
  виртуальной машине или на реальном железе. Результаты прогонов — в
  docs/STATUS.md.

## N. Сборка и поставка
- Android: flutter build apk --release --split-per-abi; подпись через
  key.properties из переменных окружения/секретов CI (ключ в репозиторий
  не коммитить).
- Windows: flutter build windows --release; упаковка — пакет msix (или
  Inno Setup, решение в ADR) и zip-вариант.
- Linux: основной путь — Flatpak. Рантайм org.gnome.Platform ветки 51
  (проверить наличие стабильной ветки на Flathub), манифест в
  packaging/flatpak/, app id в обратной нотации. Разрешения: сеть, сокет
  Wayland, доступ к GPU (dri), звук (PulseAudio/PipeWire), собственное имя
  org.mpris.MediaPlayer2.<id> на шине сессии, доступ к порталу Secrets.
  Лишних прав (доступ ко всей домашней папке и т. п.) не давать. Сборка
  Flutter-бандла выполняется в CI, в Flatpak упаковывается готовый бандл;
  проверить это решение на практике и зафиксировать в ADR.
  Запасные варианты: tar.gz с бандлом и PKGBUILD для Arch/CachyOS.
  Нативный rpm для ALT Linux — только через ADR.
  Бандл собирать на системе с достаточно старой glibc, чтобы он запускался
  на целевых дистрибутивах; проверить на реальных системах.
- Версионирование: version в pubspec.yaml, CHANGELOG.md (Keep a Changelog),
  коммиты Conventional Commits, теги релизов vX.Y.Z.

# АРХИТЕКТУРА

Слои: domain (сущности, интерфейсы, use-cases) → data (WebDAV-клиент, БД,
кэши, теги, движок) → presentation (экраны, контроллеры). Платформенный код —
только в lib/platform/{android,windows,linux} за интерфейсами (PlayerEngine,
MediaSessionBridge, SecureStore, WindowController, RangeReader).
Зависимости направлены внутрь. Бизнес-логики в виджетах нет. Весь сетевой и
файловый ввод-вывод скрыт за интерфейсами для подмены фейками. Файлы >400
строк делить. Структура lib/: core/, domain/, data/{webdav,db,indexer,tags,
covers,audio_cache,player}, presentation/{shell,library,now_playing,settings},
platform/{android,windows,linux}. Выбор реализации платформы — в одной точке
композиции (core/platform_registry), остальной код платформу не определяет.

# НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

- UI не блокируется: XML, теги, картинки, индексация — в isolate.
- Холодный старт до интерфейса с готовой БД — не более 2 с (замерить, цель
  уточнить в ADR); прокрутка списков 60 fps в profile-режиме на 50 000 треков.
- Каждая сетевая операция: таймаут, повтор, отмена.
- Логи с уровнями; пароли и заголовки Authorization маскируются.
- flutter analyze без предупреждений.
- Поведение одинаково на трёх платформах там, где это возможно; различия
  (позиция окна на Wayland, отсутствие трея в GNOME, способ медиауправления)
  перечислены в docs/PLATFORMS.md.

# КРИТЕРИИ ПРИЁМКИ

- Приложение собирается и запускается на Windows, на AOSP-эмуляторе Android
  и на Linux с GNOME 51 (Wayland).
- Библиотека AllMusic видна в трёх представлениях; трек играет, перемотка
  работает; мини-плеер виден на всех экранах.
- В кэше аудио одновременно не более двух треков; обложки ≤ 1200×1200, JPEG q85.
- Shuffle и Repeat (выкл/все/один) работают для очередей по трекам, альбому и
  исполнителю.
- Звук продолжается при погашенном экране (Android); управление медиаклавишами
  и SMTC (Windows); плеер виден в медиапанели GNOME с названием, исполнителем
  и обложкой и управляется медиаклавишами через MPRIS (Linux).
- Русские теги в cp1251 отображаются корректно.
- Linux: пароль сохраняется между запусками, в том числе внутри Flatpak;
  при недоступном Secret Service пользователь видит понятное сообщение;
  интерфейс корректен при масштабе 100–200%.
- Секретов в репозитории нет; CI зелёный на всех платформах; check_no_gms и
  check_layers проходят; AGENTS.md, SPEC, ARCHITECTURE, TECH_STACK, PLATFORMS,
  ADR, STATUS актуальны — новый агент продолжает работу без устных пояснений.
